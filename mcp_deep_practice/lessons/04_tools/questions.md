# Conceptual & Interview Questions: Tools

### Q1 [Reasoning]: Why is a fine-grained tool like `add_ticket_comment` preferred over a generic `manage_tickets(operation="add_comment", ...)`?
**Answer Rubric:**
- Discoverability: The LLM directly inspects tool names and descriptions in the system prompt rather than having to parse complex multi-branch nested schemas.
- Granular permissions: The Host can selectively allow or block specific tools (e.g. allow `search_tickets` without user confirmation, but require confirmation for `change_ticket_status`).
- Audit logging: Call logs record specific actions cleanly.

---

### Q2 [Reasoning]: What makes a tool "idempotent", and why is idempotency critical for AI agents?
**Answer Rubric:**
- An idempotent tool produces the same state regardless of how many times it is executed with the same arguments (e.g. `set_status(id, "resolved")` vs `increment_counter()`).
- AI agents running over flaky networks or timeouts frequently retry failed tool calls. If a write tool is not idempotent (e.g. `charge_card`), retrying can cause duplicate payments or data corruption.

---

### Q3 [Architecture]: What information should an MCP tool return when given an invalid ID (e.g. ticket not found)?
**Answer Rubric:**
- It should return a descriptive error message in the text content with `isError: true` (e.g. `"Error: Ticket 'T-999' not found. Available IDs: T-101, T-102"`).
- It should NOT raise an unhandled exception or crash the server process. Providing informative error text allows the LLM to inspect the response and retry with a valid ID.

---

### Q4 [Factual]: What fields are automatically generated by the MCP SDK for `@server.tool()` decorators?
**Answer Rubric:**
- `name` (from function name)
- `description` (from function docstring)
- `inputSchema` (JSON Schema object derived from Python type annotations)

---

### Q5 [Debugging]: An LLM keeps sending strings for integer arguments (`"5"` instead of `5`). How should the MCP tool be designed to handle this?
**Answer Rubric:**
- Use Pydantic or strict Python type hints (`a: int`).
- In SDK v2, Pydantic automatically parses coercible types (or returns a clear schema validation error) rather than crashing during execution.
