# Lesson 04: Tools & Capability Engineering

## 1. Learning Objectives

By the end of this lesson, you will be able to:
1. Engineer safe, discoverable, and strongly-typed MCP tools using `@server.tool()`.
2. Compare the "Monolithic Tool" anti-pattern (`do_everything(action, payload)`) against fine-grained, single-responsibility tool design.
3. Categorize tools by critical operational properties:
   - Read vs. Write (Side-effect awareness)
   - Idempotent vs. Non-Idempotent (Safe for automatic retries)
   - High-Risk vs. Low-Risk (Requires human-in-the-loop approval)
4. Implement rigorous domain validation and clear error messaging so the LLM can self-correct on bad arguments.
5. Understand tool discovery schemas generated by Python type hints and Pydantic models.

## 3. Lesson Progression

- **Stage A (Observe)**: Run `uv run python lessons/04_tools/demo.py` to observe an in-memory ticket management server with `get_ticket`, `search_tickets`, `add_comment`, and `change_status`.
- **Stage B (Explain)**: Read `concepts.md` on tool granularity, side effects, and why monolithic `execute()` tools degrade LLM performance.
- **Stage C (Modify)**: In `exercise.py`, implement the `assign_ticket` tool with typed validation, error handling, and safety metadata.
- **Stage D (Debug)**: Diagnose why unconstrained string inputs cause silent failures in tool execution.
- **Stage E (Build / Challenge)**: In `challenge.md`, decompose a dangerous `execute(action, payload)` tool into a clean, audited MCP tool surface.
